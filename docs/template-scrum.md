### 11.3 Sprint Backlog Sprint 1 (contoh terisi)

| Isian | Isi |
|---|---|
| Periode | Minggu ke-4 (1 minggu) |
| Tujuan Sprint | Aplikasi biodata dapat dikelola penuh oleh admin yang sudah login (login + CRUD + validasi dasar) |

| ID | Item | Langkah kerja konkret |

| PB-06 | Hapus data | tombol POST + `confirm()` → `hapus()` → flashdata sukses |

### 11.5 Definition of Done (contoh terisi)

1. Fitur berjalan di CodeIgniter 4 tanpa error (diuji di browser).
2. Input pengguna divalidasi di sisi server; pesan kesalahan jelas dan isian tidak hilang.
3. Semua output data dibungkus `esc()` (aman dari XSS).
4. Setiap aksi CRUD memberi umpan balik sukses/gagal (flashdata).
5. Sudah diuji memakai daftar periksa dan buktinya (screenshot) tersimpan.
6. Kode ter-*push* ke Git dengan pesan commit yang jelas.
7. Dapat didemonstrasikan di Sprint Review.

### 11.6 Sprint Review & Retrospective (contoh terisi)

**Sprint Review**
- Demo: login → tambah → ubah → hapus → logout berjalan; password tersimpan sebagai hash.
- Umpan balik PO: tampilan sudah rapi; perlu pencarian dan ringkasan jumlah per jurusan.
- Keputusan: PB-09 dinaikkan ke Sprint 2 bersama PB-08.

**Sprint Retrospective**
- **Start:** menulis kriteria penerimaan sebelum coding; commit Git harian dengan pesan jelas.
- **Stop:** mengerjakan dua fitur sekaligus; menunda pengujian sampai akhir sprint.
- **Continue:** Daily Scrum 10 menit tiap hari; daftar periksa DoD dijalankan sebelum demo.

## 12. Kesalahan umum yang harus dihindari

| Gejala | Penyebab | Solusi |
|---|---|---|
| Backlog berbunyi "buat halaman login" | Belum memakai format user story | Paksa 3W: Sebagai **siapa**, ingin **apa**, agar **apa** |
| Semua item berprioritas P0 | Tidak berani memilih prioritas | Maksimal 3-4 item P0; sisanya P1/P2 |
| Sprint 1 berisi 8 item | Tidak realistis untuk 1 minggu | Maksimal 3-5 item (contoh di atas memakai Sprint 1 lebih besar karena sudah dikerjakan pada Latihan 1-3) |
| Semua item berestimasi L | Item terlalu besar | Pecah item L menjadi beberapa S/M |
| Papan hanya di `To Do` | Sprint tidak benar-benar dijalankan | Wajibkan bukti minimal 1 item `In Progress` |
| DoD berbunyi "selesai/rapi" | DoD tidak dapat diverifikasi | Minta kriteria yang bisa diperiksa orang lain |
| Backlog tidak pernah diperbarui | Artefak dianggap tugas sekali jadi | Product Backlog = **dokumen hidup**, boleh berubah antar-Sprint |
